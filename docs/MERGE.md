# 从两个插件合并到一个安装包

统一名称：`dsh-snowluma-companion`（SnowLuma 陪伴助手），首版 1.0.0。在原 `dsh-snowluma-bridge` 仓库改名后继续维护，保留其 issues 与历史，并合入原 `dsh-companion-core` 的 Git 历史。旧核心仓库只作历史参考。

## 配置和数据

只有一个 profile bundle 和一个插件管理入口。包内部仍有桥接、陪伴、上下文三个模块，沿用两个已有配置行 ID（snowluma-bridge、companion-core）。这保留 dsh 设置服务的命名空间，不让用户重新填写 QQ Token、模型 Key、白名单或备份选择。

`deploy/migrate-profile.mjs` 仅更新 profile 的 bundle 列表、包依赖以及 YAML 中显式的旧模块名；不改其他设置内容。先停止 dsh、保留 profile 文件副本，再以业务用户运行脚本并安装包。配套脚本会被打入发行包。重复执行不会插入重复 bundle。

沿用 snowluma 平台 ID、UMO、主人私聊绑定、session ID、日志来源事件、ctx.snowluma/ctx.companion 服务、数据库与原目录。没有重新生成空会话，没有数据格式升级。SQLite schema 仍为5，普通备份格式仍为3；现有历史备份支持的选择继续可还原。

## 界面组织

统一入口的九个分组覆盖原两个设置页的全部功能。独立折叠卡片、搜索、统一设置保存、校验错误、密钥已设置状态与只读状态共同工作；设置草稿可跨组保存。正文编辑器保留独立保存按钮，已展开的正文编辑器在收起或切换分组时保持挂载以保留草稿。

静默标记只在聊天设置中编辑，主动聊天使用桥接的同一运行值。配置字段保留以兼容已有备份；界面保存时同步两处旧字段。图片输入/语音/视频集中在媒体分组；存档图片跟随消息存档；清理、到期、日志和通知集中在维护。

权限、允许存档范围、直接@与引用/关键词唤醒、管理员最高权限、主动聊天模型自主不发、群回复对象默认关闭、全部媒体、记忆、日记、主人会话备份和现有定时行为保持。完整环境备份和电脑自动同步继续不存在。

## 检查

统一的 scripts/check.sh 构建两个模块、合并前两套单元测试与两套真实 dsh e2e。迁移回归验证 bundle 去重、显式预设模块更新、配置与凭据保持；浏览器回归验证单入口、九分组、折叠/搜索、跨模块保存、无效值阻止保存、正文草稿保留及窄屏布局。

可在已准备 Chromium/Chrome 的开发机上用 `E2E_UI=1 scripts/check.sh` 运行浏览器验证。Linux 若无浏览器，先执行 `pnpm exec playwright install chromium`；也可设置 CHROME_BIN。浏览器测试仅连接临时 e2e 环境，截图在 .cache/ui-artifacts，不连接真实 QQ 或模型。

## 1.1.0 恢复入口

“备份与迁移”现分为备份计划与导出、恢复备份、迁移自检三张独立卡片。上传或选择已有包后，显示校验结果、实际文件及可恢复类别，再显式多选恢复；默认不勾选。此调整保留既有九类备份与恢复语义、备份格式和恢复前自动备份。
