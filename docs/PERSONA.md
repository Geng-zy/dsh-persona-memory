# 人格机制、编辑器与设计对比

本次参考[dsh-agent-md](https://github.com/wwsmiler1-bit/dsh-agent-md/tree/fc762b4865893999c02ec0282aa122ffacd1d400)的人格可见性和界面设计。对比依据是该提交的README、lib/persona.js、lib/index.js、lib/client.js及测试，非仅依据介绍文字。

## 两个项目如何改变人格

| 项目 | dsh-agent-md | SnowLuma陪伴助手 |
| --- | --- | --- |
| 文件来源 | 全局DSH_HOME/AGENT.md；项目内AGENT.md优先于本机项目人格，两者选其一后可叠加全局人格 | 插件数据目录/persona/persona.md；沿用现有路径，设置页、模型修改工具、外部编辑器共用现稿 |
| 注入方式 | systemPrompt.context动态计算人格，作为上下文尾消息提供给模型 | system-prompt/assemble中替换deployment:persona-prefix，人格不做模板变量展开；可移除Harness身份句 |
| 生效时机 | 下次装配时按当前会话cwd读取 | 受管会话下次模型请求读取；无需重启或新建会话 |
| 范围 | 根据工作目录选择项目人格 | 根据预设筛选，陪伴预设默认生效；核心记忆另外按主人/其他私聊/群聊隔离 |
| 默认人格为空 | 不注入自定义人格上下文 | 保留预设人格；核心记忆仍可单独生效 |
| 编辑体验 | 文件页签、路径、字数、状态、Markdown编辑及原文件入口 | 借鉴文件工具条、编辑/正文预览页签、字数和状态，增加导入导出及修订冲突保护；网页部署不尝试打开服务器文件管理器 |
| 修改人格的工具 | 主要提供文件编辑与配置界面 | 保留主人范围的模型自改工具、硬规则与可选模型审核；群聊和普通私聊没有该修改权限 |
| 历史和备份 | 写文件保留.bak | 沿用独立历史版本、回退和备份多选恢复 |
| 主题 | 宿主主题令牌，一个强调色、分层中性背景 | 借鉴此规则，九分组、搜索及折叠保留，编辑器随宿主深浅主题变化 |

两种注入方式都由dsh最终渲染。dsh可能将变化后的提示追加到后续上下文，以保留稳定前缀缓存；不能简单理解为“每次编辑都重发并替换整段历史系统消息”。本插件保留原有组装机制，因此主人/公开记忆、自改审核、其他插件服务和已有会话继续使用相同边界。

未引入“项目目录覆盖人格”。QQ机器人使用统一人格及会话权限，工作目录不应成为另一套隐式覆盖来源；也不自动读取或重命名现有文件为AGENT.md。单独再启用另一个人格插件可能叠加不同设定，需自行明确生效范围。

## 编辑器怎么用

![人格编辑器：来源、状态与Markdown工具条](images/persona-editor.png)

*截图来自隔离测试环境；文件路径和正文为测试资料。*

1. 进入“人格与核心记忆”，展开“人格”。顶部显示**已保存正文**的有效字符数、保存后的预设范围及宿主状态；编辑器内的字数统计对应**当前草稿**，两者含义不同。
2. 直接编辑，或导入UTF-8的.md/.markdown/.txt文件（最多512KB）。导入只改变草稿，不自动保存。人格与核心记忆都有各自编辑器。
3. “模型正文预览”请求服务器按**已保存的过滤设置**处理当前草稿；不调用聊天模型、不保存文件、不制造组装记录。预览用纯文本安全呈现，保留Markdown及字面量`{{...}}`，不是执行HTML或插值。
4. 点击“保存人格”或对应核心记忆的保存按钮。底部“保存所有设置”只保存开关及参数，文档正文使用编辑器自己的按钮。
5. “导出当前稿”下载当前内容，包括未保存草稿。“载入服务器版本”重新读取服务器；已有草稿时在页面内确认是否放弃。

![移动端人格编辑器](images/persona-editor-mobile.png)

### HTML注释

“忽略人格中的HTML注释”**默认关闭**，保持已有行为。开启并保存设置后，`<!-- 作者说明 -->`不进入人格组装或其他插件读取的人格服务；原稿、工具编辑内容、历史和备份均保留。未闭合注释会排除其后全部文本，因此可先用正文预览检查。过滤后没有人格正文时，保留预设原有人格，不额外清空其他系统说明。核心记忆不使用此人格注释过滤选项。

### 外部编辑与旧页面保护

保存文档时，新编辑器发送读取时的内容修订摘要。文件被另一个页面、外部编辑器或模型工具修改后，旧修订保存返回409，保留服务器新稿。先导出草稿，再载入服务器版本并合并即可；不会自动猜测合并。历史回退请求也检查修订。为兼容旧调用方，未提供revision的原API请求仍可用。

外部原子替换即使文本长度与mtime相同，也会根据ctime/inode变化重新读取。直接修改原文件不经过插件写入函数，不会凭空生成插件历史版本。

## 如何确认实际生效

“最近组装记录”来自真实请求的人格组装钩子，而非设置页打开、文件存在或预览成功。记录展示时间、会话类别、预设、人格/核心记忆字符数及是否排除；只在内存保留最近10条，重启清空，不存人格、核心记忆或聊天正文。不额外发模型请求验证。

这是**本插件组装阶段**的记录；模型最终回复仍受完整上下文影响。若其他预设启用了dsh-persona的complete完整替换，后续仍可能恢复它自己的提示；应使用本插件陪伴预设，或明确排除该预设/关闭其complete，不依据本插件的记录宣称其他插件没有覆盖。

主人核心记忆仍只给主人范围，群聊与其他私聊只获得公开核心记忆。管理员私聊权限、群白名单、普通私聊白名单、存档限制、自改人格审核及现有备份选择均保持。
