# QQ消息组合与发送失败

统一适用于正常回复和通过适配器发送的消息，不改变白名单和管理员权限。拆分后的子消息保持顺序，相邻发送间隔至少500毫秒。

| 内容 | 本插件发送方式 |
| --- | --- |
| 文字、普通图片、小黄脸、@、引用 | 保持一条图文消息；@后补空格 |
| 语音、视频、文件 | 每段独立发送，不混入@或引用 |
| 合并转发节点、已有转发 | 独立发送；节点走专用转发API |
| JSON、链接分享、音乐、联系人、位置卡片 | 保守地独立发送，不与其他正文或装饰混装 |
| 戳一戳、窗口抖动 | 独立提交；是否允许该场景由协议端判断，拒绝会记录错误 |

并非表中所有组合都被SnowLuma硬性禁止。核对v2.2.1源码：视频要求整条只有一个视频；文件走独立上传路径；转发节点不能混入普通消息；纯引用没有正文无法发送。窗口抖动只能用于普通好友私聊且必须单独发送，与群戳一戳不是同一限制。语音及卡片采用独立发送策略，避免QQ客户端对混排内容的显示差异。

来源：[官方元素策略](https://github.com/SnowLuma/SnowLuma/blob/v2.2.1/packages/protocol/src/element-manifest.ts)、[消息解析与引用校验](https://github.com/SnowLuma/SnowLuma/blob/v2.2.1/packages/onebot/src/message-parser.ts)、[文件发送路径](https://github.com/SnowLuma/SnowLuma/blob/v2.2.1/packages/onebot/src/modules/message-actions.ts)。

## @与引用放在哪里

有图文正文时，装饰和正文一起发送。装饰后紧跟独立媒体且没有图文正文时，不把装饰硬塞进媒体：引用留给后面的首条普通正文；没有后续正文则省略引用并记日志。@可单独发送通知。不会额外构造无内容的引用消息。

语音回复保持独立；开启“同时发送文字”时，@和引用加在随附文字上。仅发语音时不额外生成文字或引用。

## 失败处理

- 发送前先转换全部子消息。缺失的本地文件、转换失败会在开始发送前报错，避免本地错误造成半条已发。
- 协议端明确返回失败时，该子消息记录错误，其余子消息继续发送；最终仍向调用方报告失败，不将部分成功当成整条成功。
- 语音回复被协议端明确拒绝时，改发原文字一次；若允许群@和引用，回退文字也按设置附加。语音合成失败原有的文字回退保留。回退前复查白名单。
- 超时、断连等无法确认是否已经送达的情况，停止当前链并报告错误，不自动重发，避免重复消息。已经成功发送的子消息也不自动重发。

这不能保证QQ风控或协议端异常下必定送达；日志会保留失败原因。不要因为一条混合消息报错就盲目重发整条，先核对已收到的部分。
