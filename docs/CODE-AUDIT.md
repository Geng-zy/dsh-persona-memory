# 代码精简与功能重叠审查（2026-10-30）

基于v2.7.1源码与dsh/SDK 0.2.1-rc.2。精简修改随v2.7.2发行；本文所列功能重叠和冲突边界保留原有行为，后续另行处理。实际部署状态以部署方现场交接为准。

## 范围与方法

覆盖两个插件全部运行模块的入口/相对导入可达性、TypeScript严格构建与未使用局部检查、客户端函数引用、打包入口、配置/事件/服务契约；重点人工核对权限、消息生命周期、人格注入、记忆分域、压缩、备份恢复、会话轮换与工作区迁移。生成的上游目录和编译输出另按输入重新生成，不把清单或编译产物当作重复业务实现删除。

清理后QQ有43个TypeScript模块，人格有31个（包含各自生成的update-catalog），均能由各自运行入口引用到。UI继续通过各自build-client脚本组合；跨仓库相同实现保留独立发行能力。静态可达不等于证明每条分支正确，结论结合下列实际回归。

## 本仓库实际精简

- 删除人格端已无法选中的QQ会话导出/恢复分支、空媒体集合循环和无用会话服务依赖；删除134行旧master-sessions模块，实际QQ导入导出继续由QQ仓库负责。
- 删除Maintenance中未再调用的QQ过期存档、会话轮换/删除和媒体清理路径，只保留现行日记与月度总览；保留返回报告的旧空字段以兼容UI/API读取。
- 移除这些旧路径附带的工作区/持久化/媒体/会话检查依赖及空setCarry回调，保留人格实际使用的qqArchive.takeCarry。
- 删除无运行调用的archiveRule计算和默认存档规则；人格记忆的contextRule、forgetMode、白名单存档接口检查仍保留。相应测试不再测试失效职责，QQ轮换测试转入QQ仓库。
- 恢复选择仅校验筛选一次，当前文档修订保护、目录恢复和记忆事务保持；清单中QQ消息/媒体/完整会话统计仍输出0，兼容旧结构。
- 修正diaryTime的schema说明：只控制日记生成，不再声称同时处理QQ存档到期。

## 与dsh、SnowLuma及另一插件的关系

| 功能 | 核对结论和处理 |
| --- | --- |
| 人格与dsh自带persona/system-prompt | 有用途重叠。本插件动态替换persona段，并按会话/预设控制范围；普通网页会话默认不接管。没有必要再实现一套提示组装器。自定义预设若启用dsh-persona complete=true，可能在组装后覆盖本插件结果；保留已有排除规则与说明，不强改用户预设。 |
| 上下文压缩 | 复用BasicCompactionEngine的事务、锁、日志和/compact，扩展轮数、阈值、中文总结与整理前钩子；陪伴预设通过isolate提供自己的compaction，未再并行挂同一作用域的basic引擎。不能删掉宿主依赖，否则破坏事务及手动压缩。 |
| 工具结果裁剪 | dsh tool-result-pruner裁剪巨大工具输出；人格插件处理历史轮次与总结，目的不同，保留。 |
| AGENTS/CLAUDE工作区指令 | 陪伴预设已有agent-instructions，会加载工作区指令；人格插件不额外再加载这些文件。文件内容若与人格矛盾，仍可能影响模型，不能把它们统称人格或偷偷禁用原工具/指令功能。 |
| 时间信息 | QQ datetimeReminder与dsh time-context有信息重复：前者附QQ提示，后者补请求时间、经过时间和浏览器时区规则。两者当前都可存在，属于少量上下文开销；删除任何一方都会改变现有可配置行为，本轮保留。 |
| QQ消息存档与dsh会话日志 | QQ存档记录获准保存的原始来往，可含未唤醒消息；dsh日志记录模型实际见到的消息、工具及事件。两者不是两份同义备份。人格从qqArchive只读取聊天，自己的库保存记忆/日记进度，不再承担QQ保留轮换。 |
| 记忆生成、向量、图记忆与压缩 | 分别为提取事实、建立检索索引、关系检索及缩短当前历史。后台可能各自调用模型，不能为减少代码而合并成一次不分用途的任务。 |
| SnowLuma正向WS/HTTP与本插件反向WS | 协议端暴露API，本插件接收反向连接并消费事件，职责互补。默认HTTP/正向WS存在不代表本插件连接了三次；本插件没有再启用HTTP事件接收。保持官方接口，不删除官方默认配置。 |
| SnowLuma #sl与QQ命令权限 | 明确的权限边界：#sl由SnowLuma直接处理，不经过插件admins/白名单；/help /sid /stop /new /reset则由QQ插件检查，全部仅admins可用。#sl默认恢复是部署方既有选择，不在代码精简时自动关闭。 |
| 语音、视频、图片处理 | SnowLuma负责QQ协议和媒体传输；QQ插件的STT/TTS/生图和ffmpeg负责识别、生成及模型输入转换。dsh聊天模型/附件服务不能直接替代这些专用提供商协议。 |
| 主动聊天与dsh任务调度 | QQ插件的随机间隔/免打扰/名单/沉默规则与通用调度不同。若用户再创建同目标的定时聊天任务，可能重复唤醒；当前代码不会自动再创建另一份等价dsh计划。 |
| 两插件备份 | 各管本插件业务，最多5份；实际会话导出只在QQ插件。保留旧无owner混合包按当前插件过滤和旧设置迁移；备份说明里的跨插件数据映射不是另一套业务备份。 |
| 更新器、通知和共享UI副本 | 两插件各自开关、历史、报告和通知，允许独立安装。两边相同的更新器/公开文档读取/通知/UI不能直接删一份，否则会引入跨仓库源码依赖。公共策略仍须同步核对。混装未来不同版本时需重新核对共享CSS和服务契约，不能把当前通过当成任意版本组合保证。 |

## 保留的兼容实现

`snowluma-bridge`、`companion-core`、事件前缀和历史数据库文件名是持久化/服务标识，不是可随意替换的旧展示名。旧清单字段、旧设置映射和管理员白名单历史兼容项保留；没有更改数据库schema、备份formatVersion、用户保存的模型、命令权限、工具权限、白名单、分域和发送规则。
