# 备份文件说明与跨插件迁移

新导出的备份包会自动附带以下说明，不需要联网读取仓库才能理解源数据：

| 文件 | 内容 |
| --- | --- |
| `migration/README.md` | 人可读的入口、逐文件目录及跨插件迁移步骤 |
| `migration/files.json` | 本包实际文件的格式、用途、归属项目、迁移注意事项；设置文件还带逐字段说明 |
| `migration/sqlite-schema.json` | 包含数据库时生成：实际表、列、类型、SQL、行数、字段含义及逻辑引用 |
| `manifest.json` | 原清单加逐文件用途说明；所有说明文件也列入SHA256与字节数校验 |

只说明实际导出的文件，不自动扩大用户选中的备份范围，不重复保存一份人格、聊天、图片或记忆正文。只有设置的备份不生成虚构的数据库说明。

## 交给dsh

将完整tar.gz交给dsh，并说明目标插件及希望迁移的类别，例如：

> 阅读包内migration/README.md和files.json，核对manifest；根据目标插件当前的数据格式生成字段映射和转换结果。保留管理员私密记忆、每个群/普通私聊的独立归属、已遗忘/被取代状态、会话和附件引用。列出不支持的数据，再使用目标插件的导入接口迁移。

dsh可据此判断人格、四类核心稿、日记、长期记忆、原始聊天存档、完整逻辑会话和设置分别如何处理。它仍需检查目标插件的真实格式/API；这些说明不是让所有插件直接互认的恢复协议。

## 迁移语义

- `master`是管理员私密记忆，`public`是公共，`group:<群号>`与`user:<QQ号>`分别隔离；目标不支持分域时分开保留并报告，不公开合并。
- 只将active且未被superseded_by取代的记录当作当前有效记忆。遗忘指纹、非活跃记录与整合历史保留其语义，不能把已遗忘内容重新激活。
- 不同数据库重建主键后，同步转换关系、整合、会话和附件引用。向量模型/维度/字节序不兼容时根据正文重建。
- dsh会话保留完整事件顺序、工具调用和结果、附件；新服务器重新分配cwd、会话ID及绑定，不照搬旧绝对路径。无法表示的事件保留为旁路资料并报告。
- 设置逐项映射含义和单位，未知字段不盲写目标插件；密码、密钥、Token仍需自行配置。原始聊天可能包含用户曾经写入的敏感内容。

## 恢复兼容

仍使用备份formatVersion=3，新增说明是可选扩展。旧包无说明也能恢复；新版导入时校验说明，但不把它们当作人格、记忆或设置写入业务目录。新包的owner归属保护保留；在别的插件中迁移需要dsh编写适配，不绕过现有恢复权限。

已生成的旧备份不会被后台重写；更新插件后新导出的包才带这些说明。
