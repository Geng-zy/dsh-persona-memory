# 开发者选项：依赖与公开上游更新

两个插件分别检查、分别通知。功能默认关闭，周期默认7天；不扫描宿主、不自动升级。升级到2.4.0不会自动启用。

在本插件设置的“开发者选项 → 依赖与上游更新”中启用，配置独立邮件/微信，保存后立即检查。启用后一分钟内开始首次检查，以后按上次检查时间计算；重启保留进度。部分来源失败次日补查，通知失败一小时后重试。关闭后停止后续检查、通知及模型调用，在途请求会收到取消信号或等待已有请求结束。

## 完整范围和版本规则

[完整清单](DEPENDENCIES.md)和[JSON清单](DEPENDENCIES.json)随构建生成，来源是package.json、pnpm锁文件、源码外部模块引用及scripts/build-update-catalog.mjs中的公开来源定义，包含直接/间接、开发/测试依赖及宿主提供的接口模块。

QQ插件还覆盖SnowLuma、官方镜像构建/QQ版本定义、AstrBot/aiocqhttp移植来源、QFace小黄脸数字编号/名称与旧数据、FFmpeg、语音/生图/识别/通知服务及可选本地接入项目。人格插件覆盖其模型、向量服务及默认向量模型来源。SMTP客户端更新由nodemailer覆盖，SMTP标准或邮箱本身没有统一的“最新版”。

npm/GitHub/PyPI默认正式稳定版，排除草稿、预览、撤回和nightly等滚动构建；dsh及其同系列SDK允许预览版。Node只跟踪插件运行/开发要求所涉及的最新LTS上游，不执行本机版本命令。不巡检Ubuntu、Docker Engine、系统服务或软件包。

无发行号资源按文件提交检查，服务文档比较规范化正文摘要。首次无基准仅建立观察基线，不证明已适配；changed可能只是编辑调整，须核实正式发布。未知、失败、无可靠正式发行、需登录或空页面不当作“最新”。OSV只覆盖已收录npm安全公告，失败或未收录不能证明没有漏洞。

动态文档可用Jina Reader作可关闭的后备，只提交清单中的公开URL，不附带令牌、邮箱、推送凭据或私人配置；它自身也纳入监测。上游未公开、账号限定或灰度变更无法保证自动识别。

任意自定义HTTP、本地程序、第三方模型、工作流及扩展无法从私密配置安全推断，需要登记公开上游：

```json
[{"kind":"github","target":"owner/project","current":"1.0.0"},
 {"kind":"npm","target":"public-package","current":"1.2.3"}]
```

支持npm/pypi/github，最多50项，不接受或执行本机命令。当前版本指仓库适配/锁定基准，不是服务器实际安装版本。移植代码必须逐段比较，不整包替换；间接依赖优先通过上层包升级。

## 独立大模型和预算

在“报告模型”页选择“使用已有模型”，直接从dsh已配置列表选择；不需要手填内部ID。也可选择“单独配置API”，使用DeepSeek、魔搭、硅基流动、百炼、OpenRouter、OpenAI、Anthropic模板或自定义服务，填写基础地址、密钥和模型名称。支持OpenAI与Anthropic兼容协议，可获取模型列表和测试连接。原有已选模型保持。不借用QQ聊天、人格、记忆或日记上下文；没有终端、文件、浏览或发布工具。模型仅分析公开证据，未配置或调用失败仍生成基础文档。

默认每次32768输出token、每份报告最多8次调用、每次180秒。每次最多分析5个更新，整份报告会分批生成。32768是初始预算，不保证每批详细分析都够用；可填写50000或更大的安全整数，插件不再设置32768的业务上限。实际输出上限、思考token是否占用预算及费用由所选模型和服务商决定，超限可能被接口拒绝；不会静默降低你填写的值。这不是货币费用上限。预算未覆盖、超时、截断和无法确认的项目明确列出。相同更新沿用已有分析，“生成/重新生成”可手动重试。来源正文采集上限会注明，并保留完整链接和需补查的版本区间。

## 通知和文档

- 两个插件各自配置，不合并通知，也不要求另一个插件在场。
- 邮件支持QQ邮箱等SMTP；填写邮箱授权码。465直接TLS，其他端口要求STARTTLS。邮件正文附完整报告，并附Markdown和JSON。
- 微信支持Server酱/PushPlus，明细按长度分条，完整文档在设置页下载。按版本/资源摘要/公告及渠道去重，失败保留待发事项；一渠道成功不导致另一渠道漏发。
- 忽略不改变适配基准或依赖，清除忽略可撤销，新版本继续通知。
- 文档包括全部清单、版本/日期/来源、影响文件、模型分析、未知项，以及修改/测试/两个仓库独立发布/安装器与校验值/交接更新/部署空闲检查/回退步骤。它是任务建议，不是已实施或已验证的更新。

## 隐私和状态

白名单只输入随包清单与公开资料，不读取人格、记忆、会话、日记、备份正文、私人交接文档或宿主软件信息。模型输入和输出均过滤邮箱、IP、身份标识、私人目录、常见令牌及URL凭据/参数。通知凭据仅用于通知请求，公开仓库标识作为更新证据保留。

私人交接原稿不会自动读取或导出，应另外提供脱敏副本。预览使用纯文本，不执行上游文档中的代码或指令。报告不含发布/SSH凭据，不会自动授予接手AI权限。

状态位于各自数据目录developer/upstream-updates.json，以私密权限保存公开检查结果、通知去重/失败、忽略项和脱敏报告。它不是额外业务备份；通知密钥仍由dsh设置服务管理，新增secret字段不得进入备份或报告。

已登录接口：QQ `/api/qq-gateway/updates`，人格 `/api/companion/updates`。GET状态、report.md、manifest.json；POST check、analyze、test-mail、test-push、retry-notify、ignore、unignore。关闭时拒绝自动检查/分析/通知操作，零自动外部请求。手动“获取可用模型”和“测试模型连接”可在关闭时使用，均使用已保存设置；测试会调用一次模型，可能消耗额度。

开发者显式执行`node scripts/check-upstreams.mjs`可以检查一次公开上游，只写仓库.cache/upstream-cli，不通知、不调模型、不扫描宿主。修改适配基准应完成代码审查与测试后提交，不能将读过提醒当作已更新。

## GitHub只读令牌（可选）

可以先留空，遇到公开接口限额时再添加。打开[细粒度令牌创建页](https://github.com/settings/personal-access-tokens/new)，填写用途与有效期，Repository access选Public repositories，不添加额外或写入权限；生成后粘贴至“更多选项 → GitHub只读令牌”并保存。细粒度令牌默认只读访问公开仓库，见[GitHub官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。两个插件可以分别保存同一个只读令牌，通知仍各自独立。

更新助手分为概览、报告模型、通知、更多选项。高级用量、动态文档后备、补充来源及完整清单均可按需展开。API密钥作为secret保存，不进入报告、模型提示或设置备份；API地址也不写入更新报告。
